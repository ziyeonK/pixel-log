## 프로젝트 소개

이 프로젝트는 기록 앱이 적기만 하고 끝나는 정적인 방식이라 금방 흥미를 잃고 기록을 그만두게 되는 문제를 해결하기 위해 시작했습니다.

### 문제 상황
감정 일기 앱을 사용했지만, 입력 단계가 여러 번이라 기록이 번거롭게 느껴졌고 혼자 기록해도 아무 반응이 돌아오지 않아, 약 일주일 이후로는 앱을 열지 않게 되었습니다. 이 앱에는 알림 기능이 있었지만 그래도 그만뒀습니다. 즉 기록을 멈춘 이유는 잊어서가 아니라, 기록할 이유가 없어서였습니다.

> 당시 사용한 앱은 이름이 기억나지 않습니다. 그래서 유사 서비스 조사는 같은 분야에서 가장 많이 쓰이는 하루콩을 대상으로 했습니다. 아래 원인 분석은 하루콩이 아니라 제가 실제로 쓰다 그만둔 앱의 경험입니다.

### 원인 분석
| 원인 | 설명 |
|---|---|
| 1. 반응이 없음 | 기록해도 눈에 보이는 변화가 없어 기록할 이유가 약해짐 |
| 2. 입력 부담 | 기분, 활동, 감정 등 여러 단계로 입력해야 해서 귀찮음 |
| 3. 컨디션을 고려하지 않음 | 힘든 날에도 매일 같은 방식을 요구해서 기록이 끊김 |

### 해결 방법
픽셀 로그에서는 이모지 하나로 오늘 컨디션을 입력하면 픽셀 강아지가 내 상태를 닮아 변합니다. 아픈 날에는 이마에 밴드를 붙이고, 우울한 날에는 머리 위에 먹구름이 생깁니다. 체크리스트를 채우면 강아지가 알에서 노인까지 성장하고, 힘든 날에는 나를 돌보는 행동이 곧 강아지를 돌보는 행동이 됩니다.

| 원인 | 픽셀 로그의 해결 방법 | 조사에서 얻은 것 |
|---|---|---|
| 1. 반응이 없음 | 컨디션에 따라 캐릭터가 즉시 변화, 체크할 때마다 게이지와 연출로 반응 | 하루콩도 못 푼 부분 — 픽셀 로그의 차별점 |
| 2. 입력 부담 | 이모지 한 번 선택으로 기록 완료, 텍스트는 선택 메모 | 설계 후 조사해 보니 하루콩도 같은 방향이었음 |
| 3. 컨디션을 고려하지 않음 | 아픈 날은 체크리스트를 줄이고, 힘든 날에는 돌봄 항목을 추천 | 하루콩도 못 푼 부분 — 픽셀 로그의 차별점 |

### 핵심 사용 상황
> 아침에 몸이 안 좋아서 오늘 컨디션을 🤒(아픔)로 입력하면, 캐릭터 이마에 밴드가 붙고, 오늘 할 체크리스트를 절반으로 줄여서 고르고, 약 먹기 같은 돌봄 항목을 완료하면 캐릭터가 회복하며 달력에 돌봄 도장이 찍히는 상황

### 설계 원칙
1. **입력은 최소로**: 필수 입력은 이모지 하나
2. **기록에는 반드시 반응을**: 입력하고 체크할 때마다 캐릭터가 변함
3. **성장 기준은 모든 날 같게**: 아픈 날이라고 성장이 쉬워지지 않아, 거짓으로 입력해서 얻는 이득이 없음
4. **힘든 날의 노력도 남긴다**: 아픈 날은 체크리스트를 줄일 수 있고, 나를 돌본 행동은 보상 없는 도장으로 남김

## 구현할 기능

### 1. 처음 설정
- [x] 기본 습관 목록 입력 (최소 4개 — 성장 기준이 4개라 그보다 적으면 성장할 수 없음)
- [x] 알림 받을 시간 설정
- [x] 이미 설정한 사용자는 건너뜀 (로그인하면 서버에서 불러옴)

### 2. 컨디션 입력
- [x] 이모지 6개 중 1개 선택 (필수)
- [x] 텍스트 메모 (선택, 쓰는 대로 바로 저장)
- [x] 이모지를 고르기 전에는 [저장] 버튼 비활성화

| 이모지 | 컨디션 | 캐릭터 모습 | 체크리스트 | 돌봄 항목 |
|---|---|---|---|---|
| 😊 | 좋음 | 반달눈으로 활짝 웃고 반짝임 | 기본 목록 전체 | — |
| 🙂 | 보통 | 평소 표정 | 기본 목록 전체 | — |
| 😴 | 피곤 | 눈 감고 zzz | 기본 목록 전체 | — |
| 😢 | 우울 | 처진 눈, 눈물, 머리 위 먹구름 | 기본 목록 전체 | 추천 |
| 😠 | 화남 | 치켜뜬 눈썹, 옆에 화남 표시 | 기본 목록 전체 | 추천 |
| 🤒 | 아픔 | >< 눈, 이마에 밴드, 붉은 볼, 땀 | 직접 골라서 줄이기 (기본 목록의 절반) | 추천 |

### 3. 체크리스트

**기본 목록 (설정 화면)**
- [x] 사용자가 직접 정하는 매일 반복 습관 목록, 최소 4개
- [x] 추가·수정·삭제 가능, 다음 날부터 반영 (4개 미만으로 줄이려 하면 안내)

**오늘 목록**
- [x] 기본 목록이 매일 자동으로 나타남
- [x] 항목 추가 가능 (진행률 계산에 포함)
- [x] 수정은 체크하지 않은 항목만 가능
- [x] 삭제 불가

**아픈 날 항목 고르기**
- [x] 🤒 입력 후 "오늘은 최소 N개 이상 골라주세요" 화면 표시 (N = 기본 목록의 절반, 올림. 4개면 2개)
- [x] 최소 개수를 채우기 전에는 [확인] 버튼 비활성화
- [x] 선택은 완료 표시가 아니라는 안내 문구
- [x] 고르지 않고 나가면, 다시 들어올 때 선택 화면을 다시 표시

### 4. 돌봄 항목과 돌봄 도장
- [x] 😢 😠 🤒일 때 체크리스트 아래에 "오늘의 돌봄" 항목 표시 (앱이 제공, 사용자 추가 가능)
- [x] 돌봄 항목 완료 시 캐릭터 회복 연출

| 컨디션 | 돌봄 항목 → 연출 |
|---|---|
| 🤒 아픔 | 약 먹기 / 물 마시기 → 밴드가 물수건으로 바뀜 / 일찍 자기 → 이불 덮고 잠듦 |
| 😢 우울 | 산책 10분 → 먹구름이 걷힘 / 좋아하는 음악 듣기 → 헤드폰 / 따뜻한 음료 마시기 |
| 😠 화남 | 심호흡 3번 → 화남 표시가 줄어듦 / 물 마시기 / 잠깐 걷기 |

- [x] 돌봄 항목을 1개 이상 완료하면 달력에 돌봄 도장(💗)
- [x] 도장은 오늘의 돌봄 항목으로만 받음 (체크리스트 완료로는 받지 않음)
- [x] 도장은 모아보기만 가능, 전부 완료해도 추가 보상 없음

### 5. 성장
- [x] 하루에 체크리스트 4개 이상 완료하면 성장 게이지 +1칸 (하루 최대 1칸)
- [x] 컨디션과 관계없이 기준은 동일. 아픈 날도 4개 이상 하면 성장
- [x] 메인 화면에 오늘 진행률과 성장 게이지를 칸 단위로 따로 표시
- [x] 게이지가 다 차면 다음 단계로 성장

| 단계 | 다음 단계까지 | 대략 기간 | 모습 |
|---|---|---|---|
| 알 | 3칸 | 3일 | 얼룩무늬 알 |
| 부화 | 7칸 | 1주 | 깨진 껍질에서 빼꼼 |
| 아기 | 7칸 | 1주 | 작은 강아지, 노란 손수건 |
| 어린이 | 14칸 | 2주 | 조금 더 큰 강아지, 노란 손수건 |
| 청소년 | 21칸 | 3주 | 손수건 + 파란 모자 |
| 어른 | 28칸 | 4주 | 손수건을 졸업, 가장 큰 몸 |
| 노인 (최종) | — | 합계 80칸, 약 12주 | 바랜 귀 색, 흰 눈썹, 주름, 지팡이 |

※ 알 단계를 3칸으로 짧게 둔 이유: 기존 앱을 일주일 만에 그만둔 경험을 바탕으로, 첫 성장을 일주일 안에 경험하게 하기 위함

### 6. 기록을 빠진 날 처리
- [x] 빠진 날에는 주 2회 기회를 자동으로 사용 (월~일 기준, 기회를 쓴 날은 연속 일수에 포함하지 않음)
- [x] 기록이 없는 날은 기회 사용 여부와 상관없이 먼지가 쌓임 (기회는 퇴화만 면제)
- [x] 먼지는 3단계까지 쌓이며, 단계가 올라갈수록 몸에 얼룩이 늘고 더 꼬질해짐
- [x] 기회를 쓰지 않은 날이 5일 연속이면 성장 게이지 2칸 감소
- [x] 게이지가 0칸 아래로 내려가면 이전 단계로 내려가고, 모자란 칸은 이전 단계 게이지에서 뺌
- [x] 알 단계에서는 0칸에서 멈춤
- [x] 다시 기록하면 먼지를 털어내고 깨끗해짐

예시:
```
월·화 빠짐 → 기회 2번 사용 (연속 0일)
수·목·금·토·일 빠짐 → 일요일에 게이지 2칸 감소
```

### 7. 하루 경계와 재입력
- [x] 하루는 자정(00:00)에 끝남
- [x] 어제 기록은 새벽 2시까지 추가·수정 가능 (어제 기록 중에는 상단에 안내 띠 표시)
- [x] 00:00~02:00에 어제 기록이 비어 있으면 "어제 기록할까요?" 확인
- [x] 새벽 2시가 지나면 지난 기록은 읽기 전용 + "수정 기간이 지났어요" 안내
- [x] 컨디션은 그날 안에 다시 입력 가능

| 재입력 상황 | 처리 |
|---|---|
| 체크리스트를 완료한 뒤 컨디션 변경 | 완료한 항목은 그대로 인정 |
| 😊 → 🤒 | 완료한 항목은 유지, 남은 항목 중에서 다시 고름. 이미 오른 게이지는 유지 |
| 🤒 → 😊 | 기본 목록 전체로 돌아감, 완료한 항목은 유지 |

### 8. 달력과 이번 달 돌아보기
- [x] 날짜별 컨디션 이모지 표시
- [x] 돌봄 도장(💗), 기회 사용(💤), 먼지(🔅) 표시
- [x] 이번 달 기분 분포 막대 (컨디션별 일수 + %, 0일인 감정은 표시하지 않음)
- [x] 이번 달 요약 — 성장 칸 수 · 돌봄 도장 · 기회 사용 · 빠진 날
- [x] 그 달에 기록이 하나도 없으면 돌아보기 영역을 숨김

### 9. 알림
- [x] 사용자가 알림 시간 설정
- [x] 캐릭터 상태에 따라 문구가 달라짐
  - 아직 기록 전: "오늘 컨디션은 어때? 🙂"
  - 먼지가 쌓였을 때: "나 먼지 쌓였어… 보고 싶어 🥺"
  - 기록을 마친 뒤: "오늘도 기록해줘서 고마워 🐶"
- [x] 기기 알림 발송 (브라우저 알림, 앱이 열려 있을 때)

### 10. AI (LLM)
- [x] 캐릭터 한마디 — 컨디션을 저장하면 하루 1회, 한 줄
- [x] 한 달 돌아보기 요약 — 달력 아래, 버튼을 누를 때
- [x] 숫자만 전송, 메모는 사용자가 켰을 때만 (설정에서 전환)
- [x] "보낸 내용 보기"로 전송 내용 공개
- [x] 키가 없거나 호출 실패 시 고정 문구로 대체하고 그 사실을 화면에 표시
- [x] 이틀 넘게 비웠다가 돌아온 날은 반기는 말
- [x] 힘든 날이 3일 이어질 때만 "주변에 얘기해 봐"를 섞음 (진단·의학 조언·훈계는 하지 않음)

## 화면 구성

| 화면 | 주요 요소 |
|---|---|
| ① 로그인 | 로그인, 회원가입, 로그인 없이 이 기기에서 쓰기 |
| ② 처음 설정 | 추천 습관 고르기 + 직접 추가 (4개 이상), 알림 시간 |
| ③ 메인 | 날짜, 남은 기회, 캐릭터, 캐릭터 한마디, 오늘 진행률, 성장 게이지, 오늘 컨디션과 [다시 입력], 체크리스트, 오늘의 돌봄 |
| ④ 컨디션 입력 | 이모지 6개, 메모 입력칸, [저장] (이모지 선택 전 비활성화) |
| ⑤ 오늘 할 항목 고르기 | 최소 개수 안내, 기본 목록 선택 버튼, 선택 개수, [확인] (🤒일 때만 표시) |
| ⑥ 달력 | 날짜별 이모지·도장·기회·먼지, 이번 달 기분 분포와 요약, [AI 돌아보기] |
| ⑦ 설정 | 기본 습관 목록 편집(추가·수정·삭제), 계정, 알림 시간, 브라우저 알림, 메모 AI 전송 스위치 |

## 유사 서비스 분석 요약

### 하루콩 (조사 대상)

> 제가 쓰다 그만둔 앱은 이름이 기억나지 않아, 같은 분야에서 가장 많이 쓰이는 하루콩을 조사 대상으로 삼았습니다. 문제 정의는 제 경험에서, 비교와 차별점은 하루콩 조사에서 나왔습니다.

**기본 정보**
- 개발사 블루시그넘, 2021년 2월 출시. 2019년 1인 가구용 반려로봇을 준비하다가 인터뷰 후 "감정을 기록하는 도구"로 방향을 바꿔 시작했다.
- 글로벌 300만 다운로드 이상, DAU 약 9.5만 · MAU 약 59만(2022년 기준), 2021년 구글 '올해를 빛낸 일상생활 앱' 선정.
- 수익 구조: 기록할 때마다 약 10초 광고 + 구독(연 4,900원대) + 캐릭터 테마 스토어.

**기록 방식**
- 기분, 식사, 사람, 날씨 등 17개 카테고리 중 원하는 것만 골라 기록한다.
- 이모지 아이콘을 누르는 것만으로 기록이 완료되고, 한 줄 메모와 사진은 선택이다.
- 쌓인 기록은 캘린더 · 타임라인 · 분석 보고서(그래프)로 돌아온다.
- 미래 날짜에는 기록할 수 없어 과거와 현재에 집중하도록 되어 있다.

**조사해서 알게 된 것**
내가 겪은 '원인 2'는 하루콩도 이모지 입력으로 풀어 둔 문제였다. 하루콩 조사는 설계를 마친 뒤에 했기 때문에, 따라간 것이 아니라 같은 결론에 도달한 것이고 그 방향이 맞다는 확인이 되었다. 반면 원인 1(반응 없음)과 원인 3(컨디션 고려 없음)은 하루콩에서도 해결되지 않았다.

하루콩에서 실제로 가져온 기능은 **월간 기분 분포 하나**다. 그대로 쓰지 않고 성장 칸 수·돌봄 도장·기회·빠진 날을 같은 자리에 붙였고, 기록이 적을 때 퍼센트가 과장되지 않도록 일수를 함께 적었다.

## 목표 구현 기능 목록 및 계획

### 기술 스택
- **프론트엔드**: HTML / CSS / JavaScript (라이브러리 없이 단일 파일)
- **백엔드**: Node.js + Express
- **데이터베이스**: SQLite (로그인하지 않으면 브라우저 localStorage)
- **AI**: 마인드로직 API 게이트웨이(OpenAI 호환), 모델 solar-pro4 — API 키는 `.env`에만 두고 저장소에 올리지 않음
- 캐릭터: 32×30 픽셀 도트를 SVG로 렌더링 (참고 도안을 격자 단위로 옮긴 뒤 좌우 대칭으로 정리)


### 데이터 저장과 흐름
픽셀 로그는 로그인 없이도 쓸 수 있고, 로그인하면 서버에 저장되는 두 가지 방식을 모두 지원한다.

| 모드 | 저장 위치 | 특징 |
|---|---|---|
| 로그인 안 함 | 브라우저 localStorage | 서버 없이 동작, 오프라인 가능, 이 기기에만 남음 |
| 로그인함 | 서버의 SQLite 데이터베이스 | 기기를 바꿔도 이어서 기록, AI 기능 사용 가능 |

**선택 이유**: 기본은 기기 저장이다. 컨디션과 감정은 민감한 기록이고, 로그인부터 요구하면 "이모지 하나로 기록 끝"이라는 입력 부담 최소화 원칙과 부딪히기 때문이다. 다만 기기를 바꾸면 기록이 끊긴다는 한계가 있어, 원하는 사람만 로그인해서 서버에 저장할 수 있게 했다.

#### 백엔드 (Node.js + Express)

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/ping` | 서버가 켜져 있는지 확인 |
| POST | `/api/signup` · `/api/login` · `/api/logout` | 회원가입 · 로그인 · 로그아웃 |
| GET | `/api/state` | 설정 · 성장 상태 · 전체 기록 불러오기 |
| PUT | `/api/records/:date` | 하루 기록 저장 (UPSERT) |
| PUT | `/api/growth` · `/api/settings` | 성장 상태 · 설정 저장 |
| GET | `/api/records?month=YYYY-MM` | 달력용 월별 조회 |
| POST | `/api/ai/say` | AI 캐릭터 한마디 — 숫자만 보내고 한 줄 받기 |
| POST | `/api/ai/summary` | AI 한 달 돌아보기 — 숫자만 보내고 한 문단 받기 |
| GET | `/api/ai/status` | AI가 켜져 있는지, 어떤 모델인지 |

- 비밀번호는 bcrypt로 해시해서 저장하고, 로그인 상태는 랜덤 토큰으로 관리한다.
- 저장 요청은 약 0.4초 모았다가 한 번에 보낸다. 체크할 때마다 요청이 쏟아지지 않게 하기 위함이다.
- AI 기능은 크레딧이 드는 기능이라 로그인한 사용자만 쓸 수 있다.

#### 데이터베이스 (SQLite)

| 표 | 들어가는 것 |
|---|---|
| `users` | id, email, password(해시), created_at |
| `tokens` | token, user_id, created_at |
| `settings` | user_id, base_habits(JSON), notify_time |
| `growth` | user_id, stage, filled, miss_streak, dust_lv |
| `records` | user_id, date, cond, memo, items(JSON), care(JSON), stamped, grew, chance_used, missed, updated_at |

- `records`는 (user_id, date)가 기본 키라 하루에 한 줄만 남는다. 같은 날짜를 다시 저장하면 줄이 수정된다.
- 체크리스트와 돌봄 항목은 개수가 날마다 달라 JSON 문자열로 저장하고, 날짜·컨디션처럼 검색에 쓰는 값만 별도 열로 두었다.
- 날짜 키는 로컬 시간 기준 `YYYY-MM-DD`. UTC로 만들면 한국 시간 기준으로 하루가 밀린다.
- 회원가입 때 `base_habits`를 비워 두고, 비어 있으면 처음 설정 화면을 띄운다.

**데이터 흐름**
```
[입력] 이모지 선택 · 체크리스트 체크
   ↓
[처리] 오늘 기록 갱신 → 완료 개수 확인 → 성장 게이지·도장 판정
   ↓
[저장] 브라우저 localStorage에 캐시
       로그인 상태면 서버로 전송 → SQLite에 저장
   ↓
[AI]   로그인 상태면 서버가 숫자만 모아 LLM에 보내고 한마디를 받음
   ↓
[출력] 캐릭터 모습, 캐릭터 한마디, 오늘 진행률, 성장 게이지, 달력
   ↓
[재실행] 로그인 상태면 서버에서, 아니면 localStorage에서 복원
```

**용량**: 하루 기록이 약 200바이트라 1년치가 약 73KB다. 기기 저장(약 5MB 한도)으로도 충분하다.
