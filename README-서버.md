# 픽셀 로그 — 서버 실행 방법

## 준비
Node.js가 설치되어 있어야 합니다 (https://nodejs.org, LTS 버전).

## 실행

```bash
cd pixellog-server
npm install        # 처음 한 번만
node server.js     # 서버 시작
```

브라우저에서 http://localhost:3000 을 열면 앱이 나옵니다.
끄려면 터미널에서 Ctrl + C 를 누르면 됩니다.

VS Code에서는 터미널(Ctrl + `)을 열고 위 명령어를 그대로 치면 됩니다.

## 폴더 구성

```
pixellog-server/
├── server.js         ← 백엔드 (Express 서버 + SQLite 연결 + API)
├── package.json      ← 사용하는 라이브러리 목록
├── pixellog.db       ← 데이터베이스 파일 (처음 실행하면 자동 생성)
└── public/
    └── index.html    ← 프론트엔드 (화면 + 캐릭터 + 화면 로직)
```

## 화면 구성

앱을 열면 로그인 화면이 먼저 나옵니다.

| 선택 | 결과 |
|---|---|
| 로그인 / 회원가입 | 기록이 서버에 저장돼서 다른 기기에서도 이어서 씁니다 |
| 로그인 없이 이 기기에서 쓰기 | 브라우저에만 저장합니다 (서버 없이도 동작) |

처음 들어오면 매일 할 습관(4개 이상)과 알림 시간을 정하는 처음 설정 화면이 나옵니다. 한 번 정하면 다음부터는 바로 앱 화면으로 들어갑니다. 설정 카드의 계정 줄에서 다시 로그인하거나 로그아웃할 수 있습니다.

서버가 꺼져 있으면 로그인 입력란 대신 안내 문구가 나오고, "이 기기에서 쓰기"만 쓸 수 있습니다.

## 시간은 실제 시계로 흐릅니다

- 하루는 자정에 바뀌고, 전날 기록은 새벽 2시까지 추가·수정할 수 있습니다.
- 새벽 2시가 지나면 그 전날이 자동으로 마감됩니다 → 기록이 없으면 기회를 쓰거나(주 2회), 기회가 없으면 빠진 날로 기록되고 먼지가 쌓입니다. 5일 연속이면 성장 게이지가 2칸 줄어듭니다.
- 며칠 동안 앱을 열지 않았어도, 다시 열면 그동안의 날이 한 번에 처리됩니다.
- 설정 아래 개발자 도구(점검용)에서만 시각·단계를 임시로 바꾸거나 하루를 건너뛸 수 있습니다. 평소 사용에는 영향이 없습니다.

## 로그인하지 않아도 동작합니다

| | 저장 위치 | 특징 |
|---|---|---|
| 로그인 안 함 | 브라우저(localStorage) | 서버 없이도 동작, 이 기기에만 남음 |
| 로그인함 | 서버의 SQLite | 다른 기기에서도 이어서 기록 |

회원가입하면 빈 계정으로 시작해서 처음 설정 화면이 나옵니다. 로그인 없이 쓰던 기록이 있으면 "이 기기에서 쓰던 기록도 가져오기"를 체크했을 때만 서버로 올라갑니다. 로그인하면 서버 기록을 내려받고, 로그아웃하면 계정 기록은 이 기기에서 지워집니다. 로그인 없이 쓴 기록과 계정 기록은 브라우저에 따로 저장되어 섞이지 않습니다.

## AI 기능 (LLM)

AI는 두 군데에 들어 있습니다.

| 기능 | 언제 | 무엇을 |
|---|---|---|
| 캐릭터 한마디 | 컨디션을 저장할 때, 하루 1번 | 캐릭터 아래에 한 줄로 말을 건넴 |
| 한 달 돌아보기 | 달력 아래 [AI 돌아보기] 버튼을 누를 때 | 그 달 기록을 한 문단으로 정리 |

### 키 넣기

1. `.env.example`을 복사해서 이름을 `.env`로 바꿉니다.
2. `MINDLOGIC_API_KEY=` 뒤에 발급받은 키를 붙여넣습니다.
3. 서버를 다시 켜면 시작할 때 `AI 요약: 켜짐 (모델이름)`이 찍힙니다.

```
MINDLOGIC_API_KEY=발급받은_키
MINDLOGIC_MODEL=solar-pro4
```

> `.env`는 `.gitignore`에 들어 있어 깃허브에 올라가지 않습니다. 키를 코드 안에 직접 쓰지 마세요. 공개 저장소에 키가 올라가면 다른 사람이 크레딧을 쓸 수 있습니다.

### 쓰는 곳

마인드로직 API 게이트웨이(OpenAI 호환)를 호출합니다.

| | |
|---|---|
| 엔드포인트 | `https://factchat-cloud.mindlogic.ai/v1/gateway/chat/completions/` |
| 인증 | `Authorization: Bearer <키>` |
| 형식 | OpenAI Chat Completions와 동일 (`model` + `messages`) |

모델은 `MINDLOGIC_MODEL`로 바꿀 수 있습니다. 모델마다 크레딧 단가가 달라, 짧은 요약에는 싼 모델로 충분합니다.

### 무엇을 보내는가

메모 본문은 보내지 않습니다. 서버가 데이터베이스에서 숫자만 뽑아서 보냅니다.

```json
{ "월": "2026-10", "기록한_날": 10,
  "컨디션별_일수": { "좋음": 3, "보통": 3, "피곤": 1, "우울": 1, "화남": 1, "아픔": 1 },
  "성장한_칸": 6, "돌봄_도장": 3, "기회_사용": 1, "빠진_날": 1,
  "현재_단계": "어린이", "현재_게이지": 9 }
```

화면의 [보낸 내용 보기] 를 누르면 사용자도 이 내용을 그대로 확인할 수 있습니다.

### 실패했을 때

키가 없거나 호출이 실패하면 서버가 규칙으로 만든 문장으로 대신합니다. 화면에는 "서버 규칙으로 만든 문장"이라고 표시되어, AI가 쓴 것과 구분됩니다. 즉 AI가 안 되는 상황에서도 기능이 멈추지 않습니다.

### 로그인한 사용자만

크레딧이 드는 기능이라 로그인한 사용자만 쓸 수 있습니다. 로그인하지 않으면 버튼 대신 안내 문구가 나옵니다.

## API 목록

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/ping` | 서버가 켜져 있는지 확인 (앱이 시작할 때 한 번) |
| POST | `/api/signup` | 회원가입 (비밀번호는 bcrypt로 해시해서 저장) |
| POST | `/api/login` | 로그인, 토큰 발급 |
| POST | `/api/logout` | 토큰 삭제 |
| GET | `/api/state` | 설정·성장 상태·전체 기록을 한 번에 불러오기 |
| PUT | `/api/records/:date` | 하루 기록 저장 (있으면 수정, 없으면 추가) |
| PUT | `/api/growth` | 성장 단계·게이지 저장 |
| PUT | `/api/settings` | 기본 습관 목록·알림 시간 저장 |
| GET | `/api/records?month=2026-10` | 달력용으로 그 달 기록만 조회 |
| POST | `/api/ai/say` | 오늘 상태 숫자를 LLM에 보내 캐릭터 한마디 받기 |
| GET | `/api/ai/status` | AI 요약이 켜져 있는지, 어떤 모델인지 |
| POST | `/api/ai/summary` | 그 달 통계를 LLM에 보내 한 문단 요약 받기 |

로그인이 필요한 요청에는 `Authorization: Bearer <토큰>` 헤더가 붙습니다.

## 데이터베이스 구조 (SQLite)

| 표 | 들어가는 것 |
|---|---|
| `users` | id, email, password(해시), created_at |
| `tokens` | token, user_id, created_at |
| `settings` | user_id, base_habits(JSON), notify_time |
| `growth` | user_id, stage, filled, miss_streak, dust_lv |
| `records` | user_id, date, cond, memo, items(JSON), care(JSON), stamped, grew, chance_used, missed, updated_at |

`records`는 (user_id, date)를 기본 키로 두어 하루에 한 줄만 남습니다. 같은 날짜를 다시 저장하면 새로 추가되지 않고 그 줄이 수정됩니다.

날짜는 `YYYY-MM-DD` 형식이며 로컬 시간 기준으로 만듭니다. UTC로 만들면 한국 시간 기준으로 하루가 밀립니다.

## 설계 메모

- 비밀번호는 평문으로 저장하지 않고 bcrypt 해시로 저장합니다.
- 로그인 상태는 랜덤 토큰으로 관리합니다(`tokens` 표).
- 체크리스트와 돌봄 항목은 개수가 날마다 달라 JSON 문자열로 저장했습니다. 날짜·컨디션처럼 검색에 쓰이는 값은 별도 열로 두었습니다.
- 저장 요청은 화면에서 바로 보내지 않고 약 0.4초 모았다가 한 번에 보냅니다(체크할 때마다 요청이 쏟아지지 않도록).
